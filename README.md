# Underground Fortress

A 2D side-view survivor bunker in a zombie apocalypse, where every survivor is a real **Claude Code session**. Lidia, the captain, runs the command room at the top. Dig a room and a new session moves in. When a session finishes a turn, it rides the elevator up to report, and Lidia decides what it does next. If she can't decide, the dweller turns **red with a `!`** and waits for you.

Art: dark industrial pixel art (gunmetal, grates, red emergency light) generated with OpenArt. The client re-pixelates every asset on load (true low-res grid, limited palette, hard alpha, nearest-neighbour scaling), so the style holds even where a generated image comes out soft.

## Run it on your phone (no computer, no API key)

Everything runs on an Android phone, billed to your **Claude subscription**. Claude Code has no Android build, so a small Ubuntu layer runs inside Termux, and the fortress talks to it on `localhost`.

1. Install **Termux** from F-Droid (not the Play Store).
2. Paste this into Termux:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/thehillfire/Underground-Fortress/HEAD/scripts/install.sh | bash
   ```
3. When Claude opens, type `/login`, pick your Claude account (Pro/Max, **not** API key), approve the link, then type `/exit`. The game opens in Chrome. ⋮ → **Add to Home screen** installs it.

Later: `fortress` to play, `fortress update` to update, `fortress mock` to try it without using Claude. SETUP → *Claude account* confirms you are on the subscription. The fortress strips `ANTHROPIC_API_KEY` from its environment, so it can never bill per token. While the fortress runs, Termux holds a wake-lock so Android doesn't put the survivors to sleep. If the SDK's bundled Claude binary won't start on your phone, set `FORTRESS_CLAUDE_PATH=$(command -v claude)` inside Ubuntu.

## Run it on a computer

```bash
npm install
npm start            # http://127.0.0.1:4321
npm run mock         # same UI, fake sessions, no Claude usage
```

You need Node 20+ and Claude Code authentication on this machine, either a logged-in `claude` CLI or `ANTHROPIC_API_KEY`. The first start downloads the OpenArt art into `public/assets/`. If that fails, the game falls back to drawn pixel art.

## What's in the fortress

| Thing | How it works |
|---|---|
| **Projects (rooms)** | A room is a project; an agent is one Claude Code session working in a project. A project holds any number of agents who share its folder (or a connected repository), see each other's goals in their brief, and review each other first. Tap a room for its panel: members, **+ Add agent to this room**, room type (workshop, archive, reactor, bio lab, ops hall, garage, vault), name, goal and repository. Move an agent with ⋮ → *Project room*, or just tell Lidia ("put Scout Leads and Lead Outreach in a project called Lead Generation"). Moving keeps the agent's memory and files. Rooms that only ever held one agent close themselves once empty. Older fortresses are migrated automatically: each existing agent gets a room of its own. |
| **The bunker** | Rooms branch off the central lift along tunnels, several per level on both sides, and grow with the number of agents inside. Service ladders, generator/pump/water pockets and the dashed *+ New project* dig spot make it a network rather than a stack. On the surface, defenders on two barricade walls shoot and shove back a zombie horde. |
| **Lidia** | Tap her for a dialogue scene with her briefing, report board and texting. She runs her own Claude session with fortress tools: roster, read any agent's log, message agents, open project rooms, create agents in a project, move agents between projects, set an agent's model, hand agents data files, stop agents, update orders. She also reviews every finished turn against your **standing orders** and **precedents** (questions you answered before). She chooses one of three things: *continue* (sends the next instruction), *done*, or *escalate*, which turns the dweller red. Talk to her directly to relay orders, change policy, or open new rooms. |
| **Red `!`** | Either Lidia needs a decision, or a dweller asks permission for a risky tool. Answer in the dweller's panel. Lidia remembers your answer. |
| **Repos** | `owner/repo` or any git URL, cloned with your git credentials and assignable to any room. |
| **Connectors** | MCP servers, given to every dweller. There's a quick-add shelf, a search over the official MCP registry ("any app"), and custom http/sse/stdio servers with an optional bearer token. |
| **Skills** | The finder shallow-clones skill repos (default `anthropics/skills`, add your own in Settings), searches `SKILL.md` files, and installs to `~/.claude/skills`, so every dweller gets them. |
| **Voice** | Press `M` or the MIC button. It keeps listening through pauses (think as long as you like) and only sends when you tap **SEND** (CANCEL throws it away). The screen stays on while the mic is on, and picks the mic back up if the phone was locked. If nobody speaks for 3 minutes it stops and puts your words in the text box instead of sending. Start with "Lidia, …" or an agent's name to address them. Replies are text only. Needs Chrome/Edge/Safari speech recognition. |
| **Agent menu (⋮)** | Top right of any agent's panel: pick its model (Opus, Sonnet, Haiku, Fable), effort (low → max) and permissions (Ask me, Accept edits, Auto, Plan only, Bypass; switches even mid-turn, and the money gate still runs in Bypass), rename it, move rooms, attach a repo, stop or evict. Takes effect on its next message. Lidia's own model and effort live in SETUP. |
| **Tabs** | Each agent's panel has CHAT (only you and the agent), WORK (Lidia's orders, peer reviews, tool calls) and MISSION (goal, scores, schedules). |
| **Photos and files** | Camera button takes a photo in the app; the gallery button attaches photos, screenshots (take them with power + volume down first) or any file, up to 10 per message. Works for every agent and for Lidia. Images are shrunk to 1600px and the agent sees them; text files are readable in its workspace under `.fortress/uploads`. Messages sent while an agent is busy appear at once, marked QUEUED. |
| **Texting** | Tapping an agent (or Lidia's chat) opens a texting screen: bubbles, photos, and whatever needs you as a card in the thread (permission, money, crash, a question). Lidia and the agents react to your texts (👍 👎 ❤️ 💀 😂 ‼️ ❓ 🔥 👀) before replying, so a yes/no lands instantly; press and hold any of their messages to react back or copy it (double-tap = ❤️), and they hear about your reaction with your next text. The small ‹ › arrows above the keyboard hop between Lidia and every agent that needs you. ⓘ opens the details: mission, schedule, reviews, the behind-the-scenes work log and the ⋮ settings. |
| **Notifications** | Lidia notifies you when she comes to you: her replies and the decisions she can't make. Not when other agents finish. App open and minimized: a phone notification from the app (turn it on in SETUP → Notifications, or when you send your first text). App closed: Termux raises it, if the Termux:API app is installed (F-Droid). Tapping it opens the app. |
| **Lidia's authority** | She acts with your authority: set any agent's permission mode (bypass included) or the fortress default, approve or deny what agents are waiting on, change every SETUP setting, connect repos, manage projects and agents. Not money: those approvals stay yours, and she won't act on a request that only appears in an agent's report. While she works you see her avatar, her thinking (faded, tap "Thought for…" afterwards to reread it) and each command she runs. |
| **Customize** | In any chat, ⋮ → *Customize* (⋮ → *Settings* opens SETUP). Pick a style, **Modern** (rounded bubbles) or **Retro squares** (the original bunker look), and a color (red, green, blue, purple, pink, amber, teal, or any color from the wheel). It applies instantly, is saved as a setting (Lidia can change it too), and every theme runs exactly the same chat: only the CSS differs (`public/chat.css`, `public/js/themes.js`), so bigger themes like a spaceship or a ship at sea can be added the same way later. |
| **Staying awake** | Everything runs inside Termux on the phone (so Wi-Fi vs mobile data doesn't matter to the app itself). The server survives stray errors (logged to `data/crash.log`, last one shown in SETUP) and the launcher restarts it if it ever stops. If Termux itself is closed or killed, the app shows *The fortress is asleep* and reconnects by itself once Termux is opened. For no-touch starts, install **Termux:Boot** (F-Droid, open it once): the fortress then starts whenever the phone turns on. Also set Termux's battery to *Unrestricted* (SETUP → KEEP ALIVE) so Android doesn't stop it with the screen off. |
| **Lidia's reviews** | When an agent finishes a turn she goes through its report: did it really do the work (its tool calls, its words), is it asking anything, what would Jav want. A question she can answer (from your orders, past answers, what she's learned about you, your recent words and reactions) she answers herself and sends back to the agent. "Done" claims are inspected (read-only look at the workspace) before the agent stands down; a false claim goes back with specifics. Output a teammate is waiting on is handed to them with context. Only real calls reach you: she texts you what the agent did, where it's stuck, why she can't decide and what she'd pick. Every review is a row in her chat you can open to read her reasoning, and while she works you see "Lidia is reviewing…" with her thinking. She saves your preferences (remember_preference) and follows the trend. Switch the inspector off with `lidiaVerify`. |
| **Delegation you can trust** | `create_agent` and `message_agent` wait for real signs of life and tell Lidia whether the agent actually started, crashed, or is only queued, so she can't claim work is under way when it isn't. If a reply claims an action ("I've sent it to Scout") with no tool call behind it, the fortress makes her do it or retract it. |
| **Restarts** | Agents cut off by a restart (Termux killed) are marked *Interrupted* with a RESUME button, and carry on by themselves unless `resumeOnRestart` is off. No agent is ever red without a reason shown. |
| **Chats** | Tap CHATS (top left) for everyone you can talk to: whoever needs you on top, then working, then idle, with unread counts. Tap one and the camera flies to them and opens their chat. |
| **World** | Drag to pan, wheel or pinch to zoom, click anyone to open their panel. `L` opens Lidia, `Esc` closes. |
| **Owners** | Every agent runs its room like a business it owns: it plans, executes, verifies, and scores itself. A fellow owner walks over every few reports to read the actual work and send a score and fixes. Agents that are failing or going in circles get a peer sent to help. After hitting a goal, owners keep improving for a set number of rounds (SETUP). |
| **Money gate** | A hook runs before every tool call of every agent and Lidia, in any permission mode. Payments, purchases, transfers, subscriptions, bookings, payment-API commands, card numbers, and checkout clicks are frozen until Jav taps APPROVE. Lidia and other agents cannot approve them, and no setting disables the gate. |
| **Skills** | Armory → Skills → *Starter armory* installs design, frontend, testing, planning, debugging and review skills (anthropics/skills + obra/superpowers) for every agent. Lidia can find and install skills herself. |
| **Schedules** | The fortress is the alarm clock (Android has no cron). Agents and Lidia schedule work with a tool ("every weekday at 7:00…"), in your phone's timezone. Jobs missed while the phone was off run as soon as the fortress starts again. Listed in each agent's room and in SETUP. |
| **Usage** | A red glowing bar under the top bar shows the current session (5-hour) limit; tap it for Claude-style rows: current session and weekly limits (all models, per-model), % used and reset times. The numbers are the same ones Claude Code's `/usage` reads from claude.ai (refreshed every 3 minutes and after every turn). Near your limit (85% by default) peer reviews and polish rounds pause. |
| **Ledger** | Below the limits in the same panel to see what this month's work would have cost at API list prices, next to your plan's price ($200 for Max 20x). Broken down by survivor and Lidia, with a month-end pace. The real extra charge on your subscription is $0. |
| **Settings** | Dweller model, Lidia's model, permission mode, max automatic nudges before Lidia asks you, default effort. |
| **Lidia decides (authority tiers)** | Every decision has a tier, enforced by the server and not just asked of the model: **0** just do it, **1** do it and report in her digest, **2** ask you with a recommendation, **3** you only (money, credentials, destructive or irreversible). An escalation that isn't really tier 2+ is turned into a decisive answer ("Yes. Download them. Continue."). Money and credential questions always reach you, even if she'd answered them. Tool-permission prompts of tier 0-1 she approves herself; tier 2-3 come to you. |
| **Standing directives** | Blanket permissions ("always download free assets") she follows without asking again. Add them in DECK → COMMAND or just tell her. A directive that touches spending is refused, always. |
| **Fixes its own errors** | A crashed turn is diagnosed (rate limit, bad model, network blip, login, disk) and fixed without you: wait it out, drop a bad model, retry with backoff. After three failed tries, or when the fix is yours (log in again, free storage), she texts you at the right level (INFO / WARN / BLOCK / CRITICAL). |
| **Command Deck (DECK)** | COMMAND: what needs you, what she handled, a 0-100 priority list (Critical/High/Normal/Low/Background), standing directives, and her live, searchable thought stream with the reason for every decision. MESSAGES: the agent-to-agent log with signature checks. AUDIT: the hash-chained trail with a scrubbable, replayable timeline. ROOMS: lifecycle (persistent/ephemeral, nested, archive/restore), the task graph, shared artifacts. SAFETY: kill switch, login, export, erase. |
| **Agent mesh** | Agents get tools to message each other (REQUEST/RESPONSE/NOTIFY/ESCALATE/DELEGATE/QUERY/ACK, HMAC-signed with per-sender keys, rate-limited, injection-flagged), take tasks with success criteria and escalation rules (accept, decline, finish with evidence), share versioned artifacts, and keep memory (short, long, episodic, shared, and private memory encrypted with AES-256-GCM, searched by meaning with local embeddings). Lidia's delegations become tasks with a goal, success criteria, constraints and "escalate only if". |
| **World themes** | SETUP → World theme: Underground Fortress, Spaceship, Wild West, Pirate Cove, Cyberpunk Village. One save, same agents; only art, palette, fonts, ambient sound and Lidia's form (Overseer, Ship's AI Core, Sheriff, Captain, Mainframe) change, with an animated crossfade. Drawn in code for now; the hand-drawn art pass waits for your OpenArt credits to renew. Also: reduce motion, color-blind filters, ambient sound, keyboard focus rings. |
| **Security** | Optional passphrase (+ authenticator code) login with 15-minute tokens that renew themselves; Host/Origin checks, strict input validation, rate limits, security headers; a tool broker that keeps agents out of Claude's login, the master key and fortress data and inside their workspace for writes; outside content wrapped as untrusted data; hash-chained audit log with secrets and personal data redacted; kill switch; export and erase. Money stays hard-coded: nothing above can approve it. See `SECURITY.md`, `docs/`. |
| **One-tap launcher** | `android/` is a tiny Android app (built by GitHub Actions, served by the fortress at `/downloads/fortress-launcher.apk`; SETUP → One-tap launcher). Tap its icon: it asks Termux to start the fortress in the background (no Termux window), waits until it answers, then opens the Fortress app. If the app finds the fortress asleep, its **WAKE THE FORTRESS** button does the same. Needs, once: the APK installed, "Run commands in Termux environment" allowed, and `allow-external-apps=true` in Termux (the setup script writes it on UPDATE). It can run exactly one fixed command, `fortress start`. Termux:Widget gets a `Fortress` shortcut too. |
| **Staying alive** | The launcher shows a connect screen, plays a sound and says CONNECTED, then starts a **watchdog** (a notification you can stop): every 20 seconds it checks the fortress and, if Android killed Termux, asks Termux to start it again. It also starts after a reboot, no Termux:Boot needed. The watchdog revives the fortress; it can't stop Android killing it. To stop that: Termux and the launcher on *Unrestricted* battery, Android 14+ *Disable child process restrictions* in Developer options, or on Android 12-13 run `fortress fix-killer` in Termux once. SETUP → *Why does it stop?* shows when Android last killed it, after how long, how many agents were working and how much memory was free. Only 3 agents work at the same time by default (SETUP → *Agents working at the same time*); the rest wait in line, because a phone running many Claude sessions at once runs out of memory and Android kills Termux. The app plays a chime and says Connected when it reconnects. |
| **Live activity** | Ask an agent "what are you doing?" and it answers at once from its real log (what it's doing, for how long, its plan, what it just did, plus its latest screenshot), even mid-turn, never with a bare emoji. A working agent shows animated dots, a moving progress strip, a live timer, its plan with a done count, its current command and its latest screenshot. Agents send screenshots (`share_screenshot`) and progress notes (`post_update`); screenshots from browser tools and headless-browser files are forwarded automatically. Lidia does the same: `show_agent` posts an agent's status and screenshot, `show_jav` sends her own. |
| **Fresh start** | The first update of this version backs up the old fortress to `data/backups/` and starts with just Lidia (settings, connected apps, repos and skills kept). Deck → Safety → *Fresh start* does it again any time. |
| **Not built, on purpose** | Anything that needs servers instead of the phone (Postgres, Redis, Kubernetes, Terraform, Grafana/PagerDuty, a CDN) and any provider with an API key: Claude runs only on your subscription. Local equivalents exist: `/api/metrics` (Prometheus text), `/api/health`, encrypted-at-rest memory, local export. Passkeys/WebAuthn and OAuth login aren't built either: this is a one-person app on `127.0.0.1`. |

## Limits worth knowing

- Lidia's autopilot spends tokens on every finished turn. The *max automatic nudges* setting (default 6) caps runaway loops.
- Remote MCP servers that require interactive OAuth may not complete it headlessly. Use a bearer token when the service offers one.
- Everything binds to `127.0.0.1`. Do not expose this server publicly; it can run code on your machine.
- State lives in `data/state.json`, and workspaces in `workspaces/`.
